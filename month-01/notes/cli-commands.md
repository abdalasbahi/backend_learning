إليك قائمة شاملة ومجمعة بجميع الأوامر التي تعرضنا لها وتعرفنا عليها حتى الآن في **السطر البرمجي (Terminal / Git Bash / CMD)** و**نظام Git**:

---

### 1️⃣ أوامر الاستكشاف والتنقل (Navigation & Inspection)

- **`pwd`**: عرض مسار المجلد الحالي الذي تقف فيه (Print Working Directory).
- **`ls`**: عرض قائمة الملفات والمجلدات.
- **`ls -la`**: عرض تفصيلي لجميع الملفات والمجلدات بما فيها المخفية.

- **`cd <path>`**: التنقل بين المجلدات (Change Directory).
- **`cd .`**: المجلد الحالي.
- **`cd ..`**: العودة للمجلد الأب (المستوى الأعلى).
- **`cd ~`**: العودة لمجلد المستخدم الرئيسي.
- **`cd -`**: العودة لآخر مجلد كنت فيه.

---

### 2️⃣ أوامر إدارة الملفات والمجلدات (File & Directory Management)

- **`mkdir <dir_name>`**: إنشاء مجلد جديد.
- **`mkdir -p path/to/dir`**: إنشاء سلسلة مجلدات متداخلة دفعة واحدة وتفادي الأخطاء إذا كانت موجودة.
- **`mkdir -p folder/{sub1,sub2}`**: استخدام الأقواس `{}` لإنشاء أكثر من مجلد فرعي داخل نفس المسار دفعة واحدة.

- **`touch <file_name>`**: إنشاء ملف فارغ جديد (أو تحديث تاريخ التعديل).
- **`type nul > <file_name>`**: بديل إنشاء ملف فارغ في Windows CMD.
- **`cp <source> <dest>`**: نسخ ملف.
- **`cp -r <dir1> <dir2>`**: نسخ مجلد بكل محتوياته.

- **`mv <source> <dest>`**: نقل ملف/مجلد أو إعادة تسميته.
- **`rm <file_name>`**: حذف ملف.
- **`rm -rf <dir_name>`**: حذف مجلد بكل محتوياته بشكل نهائي وبدون تأكيد.

---

### 3️⃣ أوامر قراءة واستكشاف محتوى الملفات (File Inspection)

- **`cat <file_name>`**: طباعة كامل محتوى الملف داخل الطرفية دفعة واحدة.
- **`head -n <N> <file_name>`**: عرض أول `N` أسطر من الملف (مثال: `head -n 5 cli-commands.md`).
- **`tail -n <N> <file_name>`**: عرض آخر `N` أسطر من الملف.
- **`tail -f <log_file>`**: المراقبة الحية والحيّة للسطور الجديدة التي تُضاف إلى الملف باستمرار (يُخرج منه بـ `Ctrl + C`).

---

### 4️⃣ أوامر البحث والمعالجة وإعادة التوجيه (Pipes, Redirection & Search)

- **`echo "text"`**: طباعة نص في الطرفية.
- **`>`**: رمز إعادة التوجيه والتغطية (Overwrite)؛ يكتب النص في الملف ويمسح محتواه القديم.
- **`>>`**: رمز إعادة التوجيه والإلحاق (Append)؛ يضيف النص في نهاية الملف مع الحفاظ على المحتوى القديم.
- **`|` (Pipe)**: تمرير مخرجات أمر ليكون مدخلاً لأمر آخر (مثال: `ls -la | grep "notes"`).
- **`grep "search_term" <file_name>`**: البحث عن كلمة أو نص محدد داخل الملف بطباعة الأسطر التي تحتويه.
- **`find <path> -name "filename"`**: البحث عن موقع ملف أو مجلد داخل شجرة النظام.

---

### 5️⃣ أوامر الصلاحيات والتحكم (Permissions)

- **`chmod +x <script.sh>`**: إعطاء صلاحية التنفيذ لملف.
- **`chmod 755 <file>` / `chmod 600 <file>**`: تغيير صلاحيات الوصول للقراءة والكتابة والتنفيذ.

---

### 6️⃣ أوامر نظام التحكم بالنسخ (Git Basics - الأسبوع الثاني)

- **`git init`**: تحويل المجلد الحالي إلى مستودع Git محلي وإظهار مجلد `.git`.
- **`git status`**: فحص حالة الملفات ومعرفة الملفات المعدلة، المخزنة، والمستبعدة.
- **`git add <file_name>`**: نقل ملف محدد إلى منطقة التجهيز (Staging Area).
- **`git add .`**: نقل جميع الملفات والتعديلات الحالية إلى الـ Staging Area.

- **`git commit -m "commit message"`**: تسجيل نقطة حفظ دائم في المستودع المحلي مع رسالة توضيحية.
- **`git log`**: استعراض سجل التاريخ والتغييرات كاملة.
- **`git log --oneline`**: عرض سجل التاريخ بشكل مختصر ومكثف في خطوط فردية.git

# 🌿 توثيق الأسبوع الثالث: إدارة الفروع، الدمج والنزاعات (Git Branching & Merging)

---

### 1️⃣ إدارة الفروع (Branching)

- **`git branch`**: عرض قائمة بجميع الفروع المحلية في المستودع (يظهر سهم أو نجمة `*` بجانب الفرع النشط حالياً).
- **`git branch <branch_name>`**: إنشاء فرع جديد باسم محدد دون الانتقال إليه.
- **`git branch -d <branch_name>`**: حذف فرع محلي بشرط أن تكون قد دمجت جميع تعديلاته مسبقاً في الفرع الرئيسي.
- **`git branch -D <branch_name>`**: حذف الفرع محلياً بشكل إجباري حتى لو كان يحتوي على تعديلات غير مدموجة.

---

### 2️⃣ التنقل بين الفروع (Switching / Checkout)

- **`git checkout <branch_name>`** (أو **`git switch <branch_name>`**): التنقل والتحول للعمل على فرع آخر.
- **`git checkout -b <branch_name>`** (أو **`git switch -c <branch_name>`**): إنشاء فرع جديد والانتقال للعمل عليه فوراً في خطوة واحدة.

---

### 3️⃣ دمج الفروع (Merging)

- **`git merge <feature_branch>`**: دمج التعديلات والـ Commits الآتية من الفرع الفرعي (`feature_branch`) إلى الفرع الذي تقف عليه حالياً (عادة `master` أو `main`).

---

### 🛠️ 4️⃣ خطوات حل النزاعات يدوياً (Resolving Merge Conflicts)

تنشأ حالة النزاع عندما يقوم شخصان (أو فرعان) بتعديل **نفس السطر في نفس الملف** بطريقتين مختلفين:

1. **التعرف على المشكلة:**

- يوقف Git عملية الدمج تلقائياً وتظهر عبارة `CONFLICT (content)` في الطرفية.
- يتحول مسار الطرفية إلى الحالة التعليقية `(master|MERGING)`.

2. **قراءة علامات النزاع (Conflict Markers):**
   عند فتح الملف المتعارض في محرر الأكواد (VS Code)، تظهر الرموز التالية:

- **`<<<<<<< HEAD`**: التعديل الموجود في فرعك الحالي (`master`).
- **`=======`**: الحد الفاصل بين التعديلين.
- **`>>>>>>> <branch_name>`**: التعديل القادم من الفرع المطلوب دمجه.

3. **إصلاح النزاع وإغلاقه:**

- **التنظيف:** حذف علامات Git (`<<<<<<<`, `=======`, `>>>>>>>`) والسطور المكررة، والإبقاء على النسخة النهائية الصحيحة.
- **التجهيز:** تشغيل `git add <file_name>` لإعلام Git بأن النزاع قد حُل.
- **التوثيق:** تشغيل `git commit -m "fix: resolve merge conflict in..."` لإتمام عملية الدمج وإعادة الطرفية لوضعها الطبيعي.

---

### 🏷️ 5️⃣ التوسيم وإصدار النسخ (Git Tagging)

- **`git tag`**: عرض جميع الأوسمة (Release Tags) المسجلة في المستودع.
- **`git tag -a <v1.0> -m "message"`**: إنشاء وسم جديد مؤرخ مع رسالة توثيقية ليشير إلى إصدار نهائي أو محطة مهمة في المشروع.

# 🌐 توثيق الأسبوع الرابع: العمل السحابي والتعاون عبر GitHub

---

### 1️⃣ ربط المستودع المحلي بالسحابة (Remote Repository)

* **`git remote add origin <URL>`**: ربط المستودع المحلي بمستودع فارغ على GitHub، مع إعطائه الاسم الافتراضي `origin`.


* **`git remote -v`**: عرض قائمة المستودعات السحابية المرتبطة بمشروعك المحلي وتحقق من الروابط.

---

### 2️⃣ رفع التحديثات والأوسمة (Pushing)

* **`git push -u origin <branch_name>`**: رفع فرع محلي محدد إلى GitHub لأول مرة، وخيار `-u` (اختصار `--set-upstream`) يربط الفرع المحلي بالسحابي لتمكين الرفع والسحب المستقبلي بأوامر قصيرة.


* **`git push`**: رفع الـ Commits الجديدة للفرع المرتبط حالياً دون الحاجة لإعادة كتابة اسم المستودع أو الفرع.
* **`git push origin --tags`**: رفع جميع الأوسمة الإفراجية (Release Tags مثل `v1.0`) المسجلة محلياً إلى منصة GitHub.



---

### 3️⃣ طلبات السحب والمراجعة (Pull Requests & Code Review)

1. **إنشاء فرع الميزة:** `git checkout -b feature/<feature_name>`.


2. **توثيق التعديل:** `git add .` ثم `git commit -m "type: description"`.


3. **رفع فرع الميزة:** `git push -u origin feature/<feature_name>`.


4. **فتح الـ PR:** الانتقال لموقع GitHub والضغط على **`Compare & pull request`**.


5. **مراجعة الكود والدمج:** التأكد من عدم وجود نزاعات ثم الضغط على **`Merge pull request`** يليه **`Confirm merge`**.



---

### 4️⃣ سحب التحديثات وتزامن البيئة (Pulling & Syncing)

* **`git pull origin <branch_name>`**: جلب وتنزيل التحديثات جديدة والـ Commits المدمجة من منصة GitHub إلى جهازك المحلي ودمجها فوراً في فرعك الحالي.
